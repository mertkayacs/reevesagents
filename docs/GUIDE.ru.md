# Руководство пользователя ReevesAgents

[English](GUIDE.md) · [Deutsch](GUIDE.de.md) · [Français](GUIDE.fr.md) · [Español](GUIDE.es.md) · [Português](GUIDE.pt.md) · [Italiano](GUIDE.it.md) · [Türkçe](GUIDE.tr.md) · **Русский** · [简体中文](GUIDE.zh-Hans.md) · [العربية](GUIDE.ar.md)

Это руководство доводит вас от свежей установки до момента, когда один агент
уже ведёт остальных за вас. А когда понадобится каждая команда и каждый флаг,
всё это лежит в [README](i18n/README.ru.md).

## Что такое ReevesAgents

- Бесплатное локальное рабочее пространство, где ваши AI-агенты для работы с
  кодом (Claude Code, Codex, Hermes, DeepSeek, Kimi и другие) работают бок о
  бок на вашей машине.
- Один агент может создавать других и управлять ими через MCP. Например, сессия
  Claude Code может вести агентов Codex и Claude Code по отдельным задачам.
- Можно использовать ReevesAgents и как обычное рабочее пространство. Запустите
  нужных вам агентов и добавляйте новых командой `reevesagents add`. Они
  работают рядом, и никто никем не управляет, пока вы сами не подключите MCP.
- Стоит он поверх тех CLI, что у вас уже есть, поэтому каждый вход остаётся
  там же, где и был всегда. ReevesAgents никогда не держит у себя API-ключ и
  не прикасается к вашему трафику моделей.
- Всё его состояние умещается в несколько JSON-файлов под `~/.reeves`. Здесь
  нет ни базы данных, которую пришлось бы поднимать, ни Docker, который надо
  было бы тянуть, и в фоне ничего не висит.

## Перед началом

- macOS, Linux или WSL (нативный Windows не является целевой средой; используйте WSL).
- Node.js версии 20.19 или новее.
- tmux версии 3.0 или новее.
- Хотя бы один провайдерский CLI, установленный и с выполненным входом: Claude
  Code, Codex, OpenCode, Hermes, Kimi, DeepSeek, Pi, Qwen или Aider.

## Установка и проверка

- Установите через Homebrew: `brew install mertkayacs/reevesagents/reevesagents`
  или глобально менеджером пакетов Node вроде pnpm: `pnpm add -g reevesagents`
- Проверьте машину: `reevesagents doctor` (проверяет Node, tmux, папку состояния
  и то, какие провайдерские CLI ему видны).
- Запустите: `reevesagents`
- Предпочитаете npm, Yarn, Bun или npx? См. [Установка](i18n/README.ru.md#установка)
  в README.

## Первый запуск

Самый быстрый воспроизводимый запуск делается из командной строки. В запуске
есть один ведущий агент и любое число исполнителей, а каждый агент записывается
как `provider[:nickname[:model]]`:

```sh
reevesagents spawn claude-code:lead codex:worker \
  --name "first run" \
  --prompt "Say hello and list the files in this folder."
```

- `claude-code:lead` здесь ведущий, `codex:worker` исполнитель. Если агентов не
  указать, запуск по умолчанию получает `codex`.
- `--name` задаёт имя запуска, `--cwd` рабочую папку (по умолчанию текущую), а
  `--prompt` вставляется в каждого агента.

Предпочитаете визуальный старт? Запустите `reevesagents` для TUI или
`reevesagents web` для локального Web UI и создайте запуск там.

Не хотите планировать всю команду заранее? Запустите одного агента и
наращивайте рабочее пространство по ходу дела. `add` присоединяется к вашему
самому недавнему запуску, так что никакой id запуска копировать не придётся:

```sh
reevesagents spawn claude-code:lead
reevesagents add codex:worker
```

## Пять способов использования

К одним и тем же запускам ведут пять поверхностей. Выбирайте ту, что удобнее в
данный момент:

- **TUI** (`reevesagents`): терминальное приложение, в котором большинство и
  проводит всё время. Всё устроено как меню, так что стрелок на клавиатуре вам
  хватит.
- **Web UI** (`reevesagents web`): те же запуски на одной странице браузера,
  где в любого агента можно заглянуть вживую. Отвечает всегда и только на
  петлевом интерфейсе.
- **CLI** (`reevesagents spawn`, `runs`, `peek`, `open`, `stop`): для скриптов
  и для тех дней, когда проще напечатать команду, чем ходить по меню.
- **tmux**: то место, где агенты живут на самом деле. Каждый из них работает
  как реальный CLI в собственной панели, поэтому закрытие TUI или Web UI никого
  не прерывает.
- **Agent control** (`reevesagents attach <cli>`): включаемый вручную MCP,
  который позволяет одному агенту вести остальных. Следующий раздел разбирает
  его по шагам.

## Позвольте одному агенту управлять остальными

Это основная функция, и она выключена, пока вы её не включите.

- Включите её для своего CLI командой `reevesagents attach claude`, а если
  выполнить просто `reevesagents attach`, подключатся сразу все установленные
  CLI, которые могут размещать MCP. Экран **Agent control** в TUI и Web UI
  делает ровно то же самое.
- `reevesagents hosts` покажет текущую картину: все CLI на этой машине и какие
  из них уже подключены.
- Потом один раз перезапустите этот CLI, потому что инструменты подхватываются
  только на старте сессии (это обычный MCP, стандартный способ, которым один
  агентский инструмент открывает свои команды другому).
- С этого момента ваш агент может поставить нового агента на задачу, печатать
  в него, читать, что тот делает, и одобрять или отклонять всё, что он
  попросит.

Практический пример: подключитесь к Claude Code, перезапустите его, и из одной
сессии Claude Code вы сможете запустить агента Codex на одну задачу и второго
агента Claude Code на другую, а затем наблюдать за обоими и направлять их.

- CLI, которые сегодня могут размещать эти инструменты: claude, codex, kimi,
  qwen, opencode, hermes. OpenCode подключается вручную, так как его собственный
  шаг добавления интерактивен.
- Исполнители по умолчанию эти инструменты не получают, так что породить новых
  агентов исполнитель не может. Если хотите, чтобы он вёл собственных
  субагентов, подключите MCP и к его CLI.
- Чтобы позже отключиться: `reevesagents detach claude`.

## Повседневные задачи

- Посмотрите, что работает: `reevesagents runs` (добавьте `--json` для скриптов).
- Наблюдайте за одним агентом, не выходя из оболочки: `reevesagents peek <agent> -n 40`.
- Перейдите в панель tmux агента: `reevesagents open <agent>`.
- Остановите весь запуск: `reevesagents stop <run> --yes`.
- Остановите одного агента: `reevesagents kill <agent> --yes`.
- Посмотрите, что запрашивают агенты: `reevesagents approvals`, затем
  `approve <id>` или `deny <id>`.
- `stop` и `kill` завершают работу, а команды `delete` удаляют записи о
  завершённой работе. Все они отказываются работать без `--yes`.

## Как держать расходы под контролем

- Поставьте впереди дешёвую или бесплатную модель в роли маршрутизатора, и
  пусть она будит дорогую только тогда, когда задача того действительно стоит.
- Рутинный код и тесты как раз и есть работа для дешёвых моделей. Большую
  модель приберегите для планирования и проектирования, а не платите ей за
  шаблонный код.
- Во что бы это ни обошлось, счёт выставляют ваши провайдеры по своим обычным
  тарифам. Сам ReevesAgents ничего сверху не добавляет.

## Когда что-то идёт не так

- Начните с `reevesagents doctor`: обычно он сам называет виновника, потому
  что проверяет и Node, и tmux, и папку состояния, и каждый провайдерский CLI.
- **tmux отсутствует:** установите его (`brew install tmux` или
  `apt install tmux`) и дайте doctor это подтвердить.
- **Провайдер не обнаружен:** почти всегда он просто не установлен, или в него
  не выполнен вход. ReevesAgents может запустить только то, что есть в `PATH`
  и куда вы вошли.
- **Web UI сообщает об отсутствующих пакетах:** опциональные модули `ws` и
  `@lydell/node-pty` были пропущены при установке. Обычная переустановка
  возвращает их на место.
- **Порт уже занят:** ничего не сломалось, `reevesagents web` просто берёт
  следующий свободный порт и печатает URL. Передайте `--port <n>`, если вам
  важен конкретный.
- Подробнее в разделе [Устранение неполадок](i18n/README.ru.md#устранение-неполадок).
