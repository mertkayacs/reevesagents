# Руководство пользователя ReevesAgents

[English](GUIDE.md) · [Deutsch](GUIDE.de.md) · [Français](GUIDE.fr.md) · [Español](GUIDE.es.md) · [Português](GUIDE.pt.md) · [Italiano](GUIDE.it.md) · [Türkçe](GUIDE.tr.md) · **Русский** · [简体中文](GUIDE.zh-Hans.md) · [العربية](GUIDE.ar.md)

Простое пошаговое руководство: установите инструмент, сделайте первый запуск и
позвольте одному агенту управлять остальными. Полный справочник команд и
параметров см. в [README](i18n/README.ru.md).

## Что такое ReevesAgents

- Бесплатное локальное рабочее пространство для AI-агентов, работающих с кодом
  (Claude Code, Codex, Hermes, DeepSeek, Kimi и другие). Они работают бок о бок
  на вашей машине.
- Главная идея: один агент создаёт других и управляет ими. Агент Claude Code
  может собрать команду агентов Codex и Claude Code и вести её по отдельным
  задачам.
- Работает поверх реальных CLI, которые у вас уже есть. Авторизация у провайдера
  остаётся на стороне каждого CLI. ReevesAgents не хранит API-ключи и никогда не
  проксирует ваш трафик моделей.
- Без базы данных, без Docker, без фонового сервиса. Состояние хранится в
  локальном JSON под `~/.reeves`.

## Перед началом

- macOS, Linux или WSL (нативный Windows не является целевой средой; используйте WSL).
- Node.js версии 20.19 или новее.
- tmux версии 3.0 или новее.
- Хотя бы один провайдерский CLI, установленный и с выполненным входом: Claude
  Code, Codex, OpenCode, Hermes, Kimi, DeepSeek, Pi, Qwen или Aider.

## Установка и проверка

- Установите глобально: `npm install -g reevesagents`
- Проверьте машину: `reevesagents doctor` (проверяет Node, tmux, папку состояния
  и то, какие провайдерские CLI ему видны).
- Запустите: `reevesagents`
- Предпочитаете pnpm, Yarn, Bun, npx или Homebrew? См. [Установка](i18n/README.ru.md#установка)
  в README.

## Первый запуск

Самый быстрый воспроизводимый запуск делается из командной строки. В запуске
есть один ведущий агент и любое число исполнителей; каждый агент записывается
как `provider[:nickname[:model]]`:

```sh
reevesagents spawn claude-code:lead codex:worker \
  --name "first run" \
  --prompt "Say hello and list the files in this folder."
```

- `claude-code:lead` здесь ведущий, `codex:worker` исполнитель. Если агентов не
  указать, запуск по умолчанию получает `codex`.
- `--name` задаёт имя запуска, `--cwd` рабочую папку (по умолчанию текущую), а
  `--prompt` вставляется в каждого агента.

Предпочитаете визуальный старт? Запустите `reevesagents` для TUI или
`reevesagents web` для локального Web UI и создайте запуск там.

## Пять способов использования

К одним и тем же запускам ведут пять поверхностей. Выбирайте ту, что удобнее в
данный момент:

- **TUI** (`reevesagents`): быстрое управление с клавиатуры прямо в терминале.
- **Web UI** (`reevesagents web`): единый визуальный обзор запусков, агентов,
  живых панелей и истории. Локальный, доступен только на петлевом интерфейсе.
- **CLI** (`reevesagents spawn`, `runs`, `peek`, `open`, `stop`): скрипты,
  быстрые команды и проверки окружения.
- **tmux**: каждый агент живёт как реальный CLI в собственной панели tmux,
  поэтому сессии продолжают работать локально даже после закрытия TUI или Web UI.
- **Agent control** (`reevesagents attach <cli>`): MCP, который включается
  только вручную и позволяет одному агенту управлять остальными. Следующий
  раздел разбирает его по шагам.

## Позвольте одному агенту управлять остальными

Это основная функция, и она выключена, пока вы её не включите.

- Включите её для своего CLI: `reevesagents attach claude` (или
  `reevesagents attach`, чтобы подключить сразу все установленные CLI, которые
  могут размещать MCP). То же самое можно сделать на экране **Agent control**
  в TUI или Web UI.
- Подтвердите: `reevesagents hosts` перечисляет CLI на вашей машине и
  показывает, какие из них подключены.
- Перезагрузите свой CLI: перезапустите сессию, чтобы она подхватила новые
  инструменты (здесь используется MCP, стандартный способ, которым один
  агентский инструмент открывает свои команды другому).
- Теперь ваш агент может создавать других агентов и управлять ими: запустить
  агента на задачу, отправить ему текст или нажатия клавиш, прочитать, что он
  делает, и одобрить или отклонить его запросы.

Практический пример: подключитесь к Claude Code, перезапустите его, и из одной
сессии Claude Code вы сможете запустить агента Codex на одну задачу и второго
агента Claude Code на другую, а затем наблюдать за обоими и направлять их.

- CLI, которые сегодня могут размещать эти инструменты: claude, codex, kimi,
  qwen, opencode, hermes. OpenCode подключается вручную, так как его собственный
  шаг добавления интерактивен.
- Исполнители по умолчанию эти инструменты не получают, поэтому исполнитель не
  может запускать новых агентов. Чтобы исполнитель мог управлять собственными
  субагентами, подключите MCP и к CLI этого исполнителя.
- Чтобы позже отключиться: `reevesagents detach claude`.

## Повседневные задачи

- Посмотрите, что работает: `reevesagents runs` (добавьте `--json` для скриптов).
- Наблюдайте за одним агентом, не выходя из оболочки: `reevesagents peek <agent> -n 40`.
- Перейдите в панель tmux агента: `reevesagents open <agent>`.
- Остановите весь запуск: `reevesagents stop <run> --yes`.
- Остановите одного агента: `reevesagents kill <agent> --yes`.
- Посмотрите, что запрашивают агенты: `reevesagents approvals`, затем
  `approve <id>` или `deny <id>`.
- `stop` и `kill` завершают работу, а команды `delete` удаляют записи о
  завершённой работе. Все они отказываются работать без `--yes`.

## Как держать расходы под контролем

- Поставьте впереди более дешёвую или бесплатную модель для распределения
  задач, и пусть она передаёт тяжёлые задачи более сильному агенту только по
  необходимости.
- Пусть дешёвые модели пишут рутинный код и тесты, пока вы планируете и
  проектируете с более крупной моделью, вместо того чтобы гнать всё через одну
  дорогую модель по умолчанию.
- Квоты и оплата остаются у каждого провайдера в его CLI. Сам ReevesAgents
  ничего не добавляет к расходам.

## Когда что-то идёт не так

- Сначала запустите `reevesagents doctor`. Он проверяет Node, tmux, папку
  состояния и провайдерские CLI и говорит, что именно сломано.
- **tmux отсутствует:** установите его (`brew install tmux` или
  `apt install tmux`) и запустите doctor снова.
- **Провайдер не обнаружен:** ReevesAgents запускает только те CLI, которые
  есть в `PATH` и в которых выполнен вход. Установите нужный CLI или войдите в
  него.
- **Web UI сообщает об отсутствующих пакетах:** ему нужны `ws` и
  `@lydell/node-pty`. Переустановите пакет с включёнными опциональными
  зависимостями.
- **Порт уже занят:** `reevesagents web` стартует на `8080` и переходит на
  следующий свободный порт; передайте `--port <n>`, чтобы выбрать другой.
- Подробнее в разделе [Устранение неполадок](i18n/README.ru.md#устранение-неполадок).
